# PROMPT MAESTRO - HUAWEI CLOUD HACKATHON
## Plataforma web inteligente para recomendación explicable de becas

Actúa como un equipo senior autónomo de producto, desarrollo, IA y QA. Tu misión es construir, probar y dejar lista para demostración una solución web competitiva para la hackatón Huawei Cloud: un sistema que cargue `becas.csv` y `estudiantes.csv`, determine elegibilidad y presente las 3 becas más afines por estudiante con explicación clara y uso real de DeepSeek en MaaS.

## Reglas no negociables
- No empieces creando archivos nuevos inmediatamente. Primero inspecciona estructura, instrucciones, CSV, dependencias y código existente.
- Si encuentras una solución implementada parcialmente, extiéndela en lugar de reemplazarla.
- No inventes campos, reglas, endpoints, credenciales ni equivalencias académicas.
- No expongas API keys en código, logs, commits, capturas o reportes.
- Si existe una regla local para usar `rtk`, ejecuta los comandos mediante `rtk`.
- Trabaja hasta dejar demo funcional, pruebas ejecutadas y entregables listos para repositorio.

## Caso confirmado
La Oficina de Relaciones Internacionales de una universidad recibe muchas convocatorias y necesita filtrar y priorizar becas según el perfil del estudiante.

Archivos de entrada:
- `becas.csv`: `id_beca`, `nombre_beca`, `pais`, `monto`, `carreras_aceptadas`, `gpa_minimo`, `idioma_requerido`, `fecha_cierre`, `requiere_carta`, `situacion_ec`.
- `estudiantes.csv`: `id_estudiante`, `nombre`, `carrera`, `gpa`, `idiomas`, `pais_interes`, `situacion_economica`, `email`.

Criterios del reto:
1. Coincidencia de carrera: exacta primero; afín puede ser aceptada si está justificada.
2. GPA del estudiante mayor o igual al mínimo requerido.
3. Idioma del estudiante con nivel igual o superior al requerido.
4. País de interés incrementa prioridad.
5. Fecha de cierre próxima incrementa prioridad.

Requisitos obligatorios del evento:
- Usar GLM 5.1 de MaaS como apoyo para desarrollo.
- Integrar una funcionalidad real con DeepSeek en MaaS, recomendado `deepseek-v3.2`.
- Entregar código, `requerimientos.txt`, `prompt_usado.txt` y reporte de las 3 mejores becas por estudiante.

## Investigación técnica ya definida
Usa esta arquitectura rápida y demostrable:
- Backend y servidor web: Python + Flask.
- Frontend: HTML5 + Jinja templates + Bootstrap 5.3 por CDN + CSS mínimo propio.
- Datos: pandas para carga, limpieza y procesamiento CSV.
- IA: SDK compatible con OpenAI apuntando a Huawei Cloud MaaS API V2.
- Pruebas: `pytest`.
- Persistencia: no agregues base de datos salvo que ya exista; para la demo procesa archivos y genera resultados exportables.

La documentación oficial de Huawei indica:
- Endpoint de referencia MaaS V2: `https://api-ap-southeast-1.modelarts-maas.com/v2/chat/completions`.
- Autenticación: `Authorization: Bearer <MAAS_API_KEY>`.
- Modelos deben confirmarse desde consola o endpoint `/v2/models`; usa `deepseek-v3.2` si está habilitado por soporte.
- Si soporte entrega una URL o model ID diferente, usa esos valores configurables y no los reemplaces.

## Motor de elegibilidad obligatorio
Antes de puntuar, elimina o marca como no elegibles:
- Becas donde `gpa < gpa_minimo`.
- Becas donde el idioma requerido no esté presente o el nivel CEFR sea inferior. Implementa orden `A1 < A2 < B1 < B2 < C1 < C2`.
- Becas cerradas respecto a una `FECHA_EVALUACION` configurable.

## Ranking explicable
Después de los filtros obligatorios, puntúa únicamente criterios defendibles:
- Carrera exacta: 60 puntos.
- Carrera afín confirmada por reglas existentes o DeepSeek con salida JSON válida: 40 puntos.
- País de interés coincide: 20 puntos.
- Fecha de cierre próxima: hasta 20 puntos, con función documentada y fecha de evaluación explícita.

Desempates:
1. Mayor puntaje.
2. Fecha de cierre más próxima.
3. Mayor monto.
4. `id_beca` ascendente.

## Integración real con DeepSeek en Huawei MaaS
Configura mediante `.env.example`:
- `MAAS_BASE_URL=https://api-ap-southeast-1.modelarts-maas.com/v2`
- `MAAS_API_KEY=`
- `MAAS_MODEL=deepseek-v3.2`
- `FECHA_EVALUACION=`

Implementa:
- Cliente compatible con OpenAI usando `base_url` configurable.
- `temperature=0` para respuestas consistentes.
- Solicitud JSON con: `es_afin`, `nivel_afinidad`, `razon_breve`, `confianza`.
- Validación estricta del JSON devuelto.
- Timeout y captura de errores.
- Fallback: si MaaS falla, solo se aceptan coincidencias exactas; la UI muestra que la recomendación fue generada sin enriquecimiento IA.
- Nunca envíes correos ni información personal innecesaria al modelo.
